# PORTFOLIO-EP-007: архитектура контента

## Статус

Ready to merge via PR #8

## Цель

Отделить редактируемые данные Portfolio v2 от JSX-разметки, сохранив текущие тексты, дизайн, ссылки и публичное поведение страницы.

## В scope

- единый источник данных для услуг, проектов, этапов работы и повторяющихся внешних ссылок;
- типизированный интерфейс контента для React-страницы;
- автоматическая проверка обязательных коллекций и полей;
- проверка уникальной двухзначной нумерации услуг и этапов;
- ограниченный набор визуальных статусов проектов;
- проверка внешних ссылок на HTTPS;
- включение тестов и валидации контента в общую quality gate.

## Вне scope

- изменение утверждённых текстов или статусов проектов;
- изменение дизайна, DOM-структуры или CSS;
- добавление CMS, базы данных, формы или аналитики;
- добавление новых публичных ссылок без подтверждения.

## Техническое решение

- `app/portfolio-content.json` хранит редактируемые данные без JSX.
- `app/content.ts` задаёт TypeScript-контракт и экспортирует единый объект для страницы.
- `scripts/content-validation.mjs` проверяет данные без сторонних runtime-зависимостей.
- `scripts/content-validation.test.mjs` защищает контракт валидатора через встроенный `node:test`.
- `scripts/verify-content.mjs` проверяет фактический production-файл; команда включена в `npm run check`.
